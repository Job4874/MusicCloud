# Optional Codemagic build fallback

The local `codemagic.yaml` prepares one manual unsigned iPhone build. No Codemagic account connection, repository upload, or build has been performed by preparing this file. Obtain the user's approval before sharing this private source with another provider.

The workflow uses `mac_mini_m2`, the current stable Xcode, and a maximum duration of 15 minutes. It runs `iphone/check-models.sh` and `iphone/build-unsigned.sh`, then keeps only `iphone/build/MusicCloud-unsigned.ipa` as a build artifact. It defines no automatic events, schedules, publishing, notifications, signing credentials, or store distribution. Codemagic documents manual builds when no trigger events are configured. See [YAML configuration](https://docs.codemagic.io/yaml-basic-configuration/yaml-getting-started/) and its [unsigned native iOS example](https://docs.codemagic.io/yaml-quick-start/first-signed-build/).

Codemagic currently advertises 500 monthly macOS M2 build minutes for an individual account, refilled on the first of the month; Teams do not receive this allowance. Its official signup page says starting does not require a credit card. This allowance is limited; the pricing page also lists paid usage beyond it. The YAML timeout limits one build's duration and does not configure account billing. See [current pricing](https://codemagic.io/pricing/), [personal-account pricing details](https://docs.codemagic.io/billing/pricing/), and [the official signup statement](https://codemagic.io/ionic-continuous-integration/).

Before any approved build, use the personal free account, confirm enough included minutes remain, and confirm billing is disabled in that selected account. Do not add a payment method, enable billing, select pay-as-you-go, use a paid machine, or enable automatic builds. Stop if the service requires payment or the free allowance is unavailable. The official [billing documentation](https://docs.codemagic.io/billing/billing/) says paid features require enabling billing and confirming a credit card; account and team billing are separate. The [FAQ](https://docs.codemagic.io/getting-started/faq/) describes waiting for the allowance to renew or choosing paid billing after exhaustion. No separate hard spending cap is documented. An existing account's payment state must be checked in its UI. No payment-free result is implied by the YAML alone.

After approval and the account checks, share only the audited private source repository with the provider, select `musiccloud-iphone-unsigned`, and start one manual build. Inspect its actual result before claiming success. A successful output remains unsigned and needs separate personal signing and USB installation from Windows; see [the USB guide](USB-AND-INSTALL.md). No Apple Account, signing key, certificate, music file, playlist export, or browser capture belongs in this workflow.
